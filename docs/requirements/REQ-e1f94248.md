## Description

面向"给 URL + 自然语言任务就要结果"的使用者：他们只描述想要什么数据，不关心站点结构、渲染方式或数据清洗。

问题：

- 多样站点需要多样的抓取策略——有的页面是静态 HTML，有的依赖客户端渲染；有的目标数据能用确定的选择器定位，有的只能靠语义理解推断。用一把锤子敲所有站点，注定失败。
- 数据落盘缺乏契约——没有字段集合与去重约定时，同一站点重跑会漂移字段结构、产生重复记录、写入空值脏数据。此前的量子位抓取缺陷正是这三类问题（schema 漂移 / 重复 / 空值）的实测暴露。

方案：

- 回归第一性原理。抓取 agent 的本质动作只有三个：取（Fetch）、懂（Extract）、存（Save）。一切工具切分都回归这三个原子动作，拒绝按技术实现冗余拆分。
- 提供三个本质工具，agent 根据具体任务自主组合，即可完成任意抓取任务；策略差异（静态 vs 渲染、确定性 vs 语义抽取）内化为工具的参数，而非并列成多个工具。
- 让数据落盘带契约保证质量：使用者声明字段集合与去重键，落盘端据此校验与去重。
- P1 产出 = 取 / 懂 / 存三个本质工具 + 数据契约 + 真实测试背书。

## 本质工具定义

**取 Fetch**
- 输入：URL。
- 输出：页面内容与其中链接。
- 可选渲染开关：默认静态；内容不足或失败时，agent 自主改用浏览器渲染再取。
- 分页不作为独立工具，而是 agent 从返回的链接中识别"下一页"并再次调用"取"。

**懂 Extract**
- 输入：页面内容与抽取意图。
- 输出：结构化记录。
- 支持两种路径：给定明确结构时走确定性选择器（快速、零模型成本）；结构模糊时走 LLM 语义抽取（通用）。

**存 Save**
- 输入：记录数据，可选字段集合（schema）与去重键。
- 带契约：缺字段拒绝、同去重键跳过、内容全空过滤。

## Acceptance Criteria

- [ ] agent 通过"取"能对静态页面取得内容与链接；内容不足或失败时能改用渲染取得渲染后内容
- [ ] agent 通过"取"能识别返回链接中的分页并连续抓取多页（分页内化于取，非独立工具）
- [ ] agent 通过"懂"能用确定性选择器从页面提取目标数据
- [ ] agent 通过"懂"能用 LLM 按字段说明从页面语义化抽取结构化记录
- [ ] agent 通过"存"落盘时可声明字段集合与去重键：缺字段记录被拒、同去重键重复被跳过、全空内容被过滤
- [ ] 重跑同一站点，数据契约保证不产生重复记录、字段结构一致（验证此前量子位暴露的 schema 漂移/重复/空值三缺陷已修复）
- [ ] 全部测试真实 API/网络、禁 mock，`npm test` 一键通过
- [ ] 给真实站点 URL + 自然语言任务，agent 能组合取/懂/存完成并产出结构化结果

## Notes

约束：

- Node >= 22.19。
- 真实 LLM API、真实网络，禁 mock。
- Docker 可用，但 P1 不使用。

设计哲学：

- 三本质工具（取/懂/存），策略内化参数，拒绝冗余拆分。

P1 明确不含（留待 P2+）：

- 自适应造工具 / 元工具。
- Docker 沙箱。
- 工具库持久化。
- 深度反爬对抗。

已知限制与开放问题：

- 取：动态生成或需登录的分页可能无法识别与跟随；深度反爬（验证码、指纹）不在范围内。
- 懂：LLM 抽取质量依赖模型能力与页面内容质量，可能存在抽取偏差；确定性选择器依赖使用者/agent 对结构的正确判断。
- 存：契约校验的成本与性能影响待评估。
