## Description

面向需要抓取登录墙、验证码、交互式组件之后内容的使用者。

**设计哲学**：不求全面但求精细，第一性原理。承认 agent 的能力边界，把人作为系统的一个组件：agent 做擅长的探索、抽取、导航，人做擅长的登录、验证码、复杂交互、判断。关键不是虚假的全自动，而是 agent 知道"何时该求助、如何让人能接手"。

**问题**：纯自动 agent 遇到登录、验证码、拖拽等需要人的操作时会卡死或盲目重试，无法完成任务；而强行追求全自动并不现实。

**方案**：给 agent 增加"求助"这一本质能力——遇到需要人的场景时主动暂停，并弹出人可操作的真实浏览器窗口；人完成交互（登录、验证码、拖拽）后，agent 在同一会话（登录态保留）中接管继续。

**产出**：人与 agent 协作完成此前无法完成的抓取任务。

## Acceptance Criteria

- [ ] agent 拥有"求助"能力：遇到需要人操作的场景（登录/验证码/拖拽/权限墙）时，能主动发起求助并说明需要人做什么
- [ ] 求助时弹出人可操作的真实浏览器窗口（有头模式），显示目标页面
- [ ] 人在该窗口完成交互后，能通过简单方式（如回车）告知 agent 继续
- [ ] 人完成交互后，agent 在同一会话中继续抓取，登录态/Cookie 自然保留（同一浏览器上下文延续）
- [ ] 求助期间 agent 暂停等待，不会并发执行其他动作导致状态混乱
- [ ] 人取消或中断（如 Ctrl+C）时，agent 能正确清理浏览器资源并退出
- [ ] 不需要人介入的任务，agent 仍以无头模式高效运行（有头窗口仅在需要时出现）
- [ ] 求助与接管过程被记录进 trace（何时求助、人操作耗时、何时接管）
- [ ] 提供一个需要登录的真实场景验证：agent 求助 → 人登录 → agent 继续抓到登录后内容（可用测试账号/模拟站点）
- [ ] 全部测试真实运行、禁 mock（人机交互环节可用受控方式模拟人的回车动作），npm test 一键通过

## Notes

**约束**
- 运行环境要求 Node.js >= 22.19
- 运行与测试均依赖真实 LLM，禁止使用 mock
- 不破坏既有的取/懂/存内核与全量 trace 能力

**定位**
- 求助是第 4 个本质动作，与取、懂、存并列
- 有头窗口仅在需要时出现，默认无头
- 登录态延续依靠共享浏览器上下文

**不在 P3 范围内**
- 自适应造工具 / 元工具 / Docker（后续再议）
- 自动验证码识别（不做，交给人来做）

**已知限制**
- 需要人在场
- 依赖 Windows 桌面环境弹窗
