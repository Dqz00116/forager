## Description

面向需要自动抓取网页结构化数据的用户（如数据分析、研究、聚合场景的开发者与使用者）。

**问题**：传统爬虫要求用户为每个目标站点手工编写解析规则（选择器、正则等），上手成本高；且站点结构一旦调整，解析规则即失效，维护非常脆弱。

**方案**：以 LLM agent 作为爬虫的"大脑"全程驱动抓取过程——agent 自主探索站点、识别分页结构、理解页面内容并抽取结构化记录，用户无需预定义任何解析规则。

**MVP 预期产出**：一个可配置、可运行、有完整文档、有真实测试背书的命令行（CLI）爬虫工具。本阶段目标是将已有验证原型的能力固化并补齐文档，不引入新功能。

## Acceptance Criteria

- [ ] 用户完成 API key 与模型配置后，能通过一条 CLI 命令对指定入口 URL 发起自主抓取，全程无需编写解析代码
- [ ] 对静态页面，agent 能抓取页面内容并从中抽取结构化记录（记录含可辨识的字段与值）
- [ ] agent 能自主识别入口页面的分页链接并跟随翻页，连续抓取多页并汇总各页记录
- [ ] 抓取到的记录以 JSONL 格式持久化到本地文件，且每行为一次解析即可得到的 JSON 对象（不存在 JSON 字符串嵌套的双重编码）
- [ ] 当页面内容依赖客户端渲染时，agent 能启用浏览器渲染兜底，成功获取并抽取渲染后的内容
- [ ] 缺少 API key 或模型配置错误时，工具输出清晰、面向用户的中文错误提示并正常退出，而非抛出未处理异常堆栈
- [ ] 进程被用户中断（Ctrl+C）时，工具能正确清理已启动的浏览器等外部资源后再退出，不残留占用
- [ ] 全部测试基于真实 LLM API 运行（不使用任何 mock），且测试套件可通过 `npm test` 一条命令运行并全部通过
- [ ] 项目提供完整使用文档，覆盖安装、配置（API key 与模型）、运行方式与常见问题故障排查

## Notes

**约束**
- 运行环境要求 Node.js >= 22.19
- 运行与测试均依赖真实 LLM API 服务，需有效的 API key
- 禁止使用 mock：所有测试必须走真实 API

**已知限制（不在 MVP 范围内）**
- 反爬对抗与代理支持不在本期范围
- 不引入数据库，数据仅以本地文件形式持久化

**开放问题**
- 目标站点抓取的合规性（robots 协议、站点服务条款等）由使用者自行确认与负责
