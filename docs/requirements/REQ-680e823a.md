## Description

这是一个 **bug 修复**（源自知乎实战），非新特性。

**问题**：`request_human` 以"等回车"作为"人工已完成"的完成信号，依赖前台 TTY stdin。在后台 / 无 TTY 场景下回车无法送达，导致用户在浏览器中已完成交互（如知乎登录）后，agent 仍永久阻塞（死锁）。

**修复思路**：把完成确认从"等待主观信号（回车）"改为"轮询客观状态"——agent 求助后周期性检测页面的可观测变化（URL 离开登录页、到达目标页、登录后元素出现 / 消失），人完成后 agent 自动继续，无需任何手动动作。回车模式保留为 fallback。

## Acceptance Criteria

- [x] agent 求助后无需回车即可检测人已完成（轮询页面状态）
- [x] 后台 / 无 TTY 场景不死锁
- [x] 回车模式保留为 fallback
- [x] 全部测试真实运行禁 mock，`npm test` 通过
