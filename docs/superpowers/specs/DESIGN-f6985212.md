# pi-crawler MVP 设计

## Overview

pi-crawler 是一个以 pi-agent 作为大脑、全程驱动的探索式爬虫 CLI。LLM agent 不再依赖固定编排脚本，而是通过一组最小工具（抓取页面、保存记录、查询已保存内容、宣告完成）自主决定探索路径与停止时机。本 MVP 的目标不是扩展新能力，而是把已经跑通的原型**固化为工程化、可测试、有文档的工具**：清晰的分层结构、类型化错误处理、集中配置校验，以及真实集成测试覆盖。

## Architecture

```
cli.ts (入口/参数/信号清理)
  └─ agent.ts (装配 pi-agent-core Agent + 爬虫 systemPrompt + sessionId)
       └─ tools.ts (4 个 AgentTool: fetch_page/save_record/list_saved/finish)
            └─ page.ts (抓取与页面转换: fetchStatic/renderDynamic/pageToLLMView)
config.ts (集中配置，启动 fail-fast)  errors.ts (类型化错误)
```

各层职责：

- **cli.ts**：进程入口。解析命令行参数、加载配置、顶层捕获错误并映射 exitCode、注册 SIGINT/SIGTERM 信号清理（终止 Playwright 浏览器等资源）。
- **agent.ts**：装配层。用 pi-agent-core 构造 `Agent`，注入爬虫专用 systemPrompt 与 sessionId，串联工具集与事件流。
- **tools.ts**：定义 4 个 AgentTool——`fetch_page`（抓取并转换为 LLM 视图）、`save_record`（结构化数据落盘 JSONL）、`list_saved`（查询已保存记录）、`finish`（agent 宣告任务完成）。
- **page.ts**：抓取与页面表示转换——`fetchStatic`（静态 HTTP 抓取）、`renderDynamic`（Playwright chromium 渲染兜底）、`pageToLLMView`（HTML → Markdown + 链接清单）。
- **config.ts**：集中读取与校验环境变量，启动时 fail-fast。
- **errors.ts**：类型化错误层级，供 CLI 区分可操作错误与编程错误。

模型层：pi-ai → OpenCode Go provider → `https://opencode.ai/zen/go/v1`，模型 `muse-spark-1.3-contributor`。

## Key Design Decisions

1. **pi-agent-core 而非 pi-coding-agent SDK**。后者内置编码工具和默认 systemPrompt，对爬虫场景是累赘；agent-core 提供干净的 agent 循环 + 工具调用 + 事件流，恰好覆盖所需能力且不引入无关负担。
2. **sessionId 注入**。OpenCode Go 端点强制 `x-opencode-session` 头用于会话路由；给 `new Agent({sessionId})` 传值，pi-ai 的 `withOpenCodeSessionHeader` 自动完成头部注入，无需手工处理 HTTP 层。
3. **模型 ID = muse-spark-1.3-contributor**。Go 目录中只有带 `-contributor` 后缀的免费模型可用（裸 `muse-spark-1.3` 位于 Zen 目录且要求 OpenCode 客户端）。
4. **数据落盘 JSONL + save_record 双重编码防御**。LLM 可能把 `data` 参数传成 JSON 字符串而非对象；`save_record` 在落盘前对字符串执行 `JSON.parse` 规范化为对象，防御双重编码导致的数据损坏。
5. **页面表示 = Markdown + 链接清单**。用 turndown 把 HTML 转为 markdown 喂给 LLM（token 友好、保留语义结构），用 cheerio 提取链接并绝对化（补全相对 URL）；markdown 超过 12000 字符时截断。
6. **双模抓取**。默认静态 `fetch`（快、资源占用低）；当内容为空或抓取失败时，agent 自主决定改用 `render_page`（Playwright chromium 渲染），作为 JS 重度页面的兜底路径。
7. **类型化错误层 errors.ts**。`AppError` 基类 + `ConfigError` / `FetchError` / `RenderError` / `ModelError`，替代裸 `Error`，使 CLI 能区分可操作错误（配置缺失、网络失败等）与编程错误。
8. **测试禁 mock**。vitest + 真实 OpenCode API 调用 + 真实靶场站点，符合 zero_mocks 约束——测试验证的是真实链路行为，而非 mock 的假设。

## Error Handling

类型化错误层级：

| 类 | code | 说明 |
|---|---|---|
| `AppError` | （基类） | 携带 code 与 `isOperational` 标志 |
| `ConfigError` | `CONFIG_ERROR` | 环境变量缺失/非法 |
| `FetchError` | `FETCH_ERROR` | 静态抓取失败 |
| `RenderError` | `RENDER_ERROR` | Playwright 渲染失败 |
| `ModelError` | `MODEL_ERROR` | LLM 调用失败 |

CLI 顶层统一捕获：若 `AppError.isOperational` 为真，打印 `[code] message`（面向用户的一行可操作信息）；否则按编程错误处理，打印完整 stack，并以 `exitCode = 1` 退出。

## Configuration

| 环境变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `OPENCODE_API_KEY` | 是 | — | OpenCode API 密钥 |
| `CRAWLER_MODEL` | 否 | `muse-spark-1.3-contributor` | 使用的模型 ID |
| `OPENCODE_SESSION_ID` | 否 | — | 会话 ID（会话路由头） |

所有环境变量由 `config.ts` 集中读取与校验，启动时 fail-fast：必填项缺失或取值非法立即报 `ConfigError` 退出，而不是在运行中途失败。

## Testing Strategy

禁 mock 原则下，真实集成测试分两层：

- **(a) 无需网络的纯函数测试**：`pageToLLMView`、`extractLinks`、`truncate`、`save_record` 双重编码还原、config 校验。
- **(b) 真实 API/网络测试**：`fetchStatic` 抓取真实靶场 `quotes.toscrape.com`；LLM 最小推理调用；端到端 agent 抓取 2 页并落盘验证。

通过 `npm test`（`vitest run`）运行。

## Out of Scope

MVP 不做：

- 反爬/代理池
- 数据库
- 分布式队列
- 增量调度
- chatbot 接口

## Open Questions

- Playwright 渲染在 CI/无显示环境的稳定性。
- 超长页面的 token 成本控制（虽本期 LLM 管够，但截断策略仍必要）。
