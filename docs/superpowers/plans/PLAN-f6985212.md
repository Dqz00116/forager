## Goal

将已验证的 LLM 驱动爬虫原型固化为可交付的 pi-crawler MVP：补齐错误层与进程健壮性、移除死依赖、建立真实 API 测试体系并完善文档，满足 REQ-f6985212 全部 9 条验收标准，不引入新功能。

## Tasks

### T1 移除死依赖 crawlee

- **要做什么**：从 `package.json` 的 dependencies 中删除 `crawlee`（源码从未 import 它），并运行 `npm install` 刷新 `package-lock.json`，保持依赖树干净。
- **触及文件**：`package.json`、`package-lock.json`
- **验证方式**：`npm run typecheck` 通过；`npm prune` / 重新 `npm install` 后源码编译与运行不受影响。

### T2 新建 src/errors.ts

- **要做什么**：创建统一错误层：`AppError` 基类（携带 `code`、`message`、`isOperational` 标志，操作型错误默认 `isOperational = true`），并派生四个子类：`ConfigError`（配置缺失/非法）、`FetchError`（网络/HTTP 抓取失败，携带 status）、`RenderError`（浏览器渲染兜底失败）、`ModelError`（模型不存在或调用失败）。
- **触及文件**：`src/errors.ts`（新建）
- **验证方式**：`npm run typecheck` 通过；各子类可被 `instanceof AppError` 识别且 `code` 值正确（在 T6 中配合单元测试覆盖）。

### T3 接入错误层

- **要做什么**：
  - `config.ts`：启动 fail-fast 时，缺失必填配置项改为抛出 `ConfigError`（提示缺哪个 key、如何配置）。
  - `page.ts`：`fetchStatic` 中两处裸 `throw` 改为 `FetchError`（HTTP 非 2xx 时携带 status）；`renderDynamic` 失败时包裹为 `RenderError`。
  - `agent.ts`：模型不存在（`muse-spark-1.3-contributor` 不可用等）场景改抛 `ModelError`。
- **触及文件**：`src/config.ts`、`src/page.ts`、`src/agent.ts`
- **验证方式**：`npm run typecheck` 通过；构造缺 key 环境运行 CLI，确认抛出的是 `ConfigError` 而非裸 Error。

### T4 cli.ts 健壮性

- **要做什么**：
  - URL 参数解析失败时输出友好的中文提示并正常退出（非 0 退出码 + 说明，不打印异常堆栈）。
  - 注册 `SIGINT` / `SIGTERM` handler：调用 `closeBrowser()` 清理浏览器等外部资源后以退出码 130 退出。
  - 将 `createCrawlerAgent` 的调用移入 `try` 块内，使其抛出的错误也能被顶层 catch 捕获。
  - 顶层 catch 区分 `AppError.isOperational`：操作型错误只打印面向用户的中文 message；非操作型（编程错误）才打印完整堆栈。
- **触及文件**：`src/cli.ts`
- **验证方式**：手动运行——传非法 URL、缺 `OPENCODE_API_KEY`、运行中按 Ctrl+C，三种场景均得到清晰中文提示且无未处理异常堆栈，Ctrl+C 后无浏览器进程残留。

### T5 调整 tsconfig include

- **要做什么**：`tsconfig.json` 的 `include` 从 `["src"]` 改为包含 `test/` 目录（如 `["src", "test"]`），使新增测试纳入类型检查。
- **触及文件**：`tsconfig.json`
- **验证方式**：`npm run typecheck` 对 `test/` 下文件同样生效（T6/T7 完成后无类型错误）。

### T6 纯函数单元测试

- **要做什么**：新建 `test/units.test.ts`，覆盖不依赖网络的纯逻辑：
  - `pageToLLMView`：markdown 视图生成正确；
  - `extractLinks`：链接提取结果正确；
  - `truncate`：超长文本按 `MARKDOWN_LIMIT` 截断、短文本原样保留；
  - `save_record` 工具：记录值中嵌套 JSON 字符串被还原为对象（消除双重编码）；
  - `config`：缺失必填 key 时抛出 `ConfigError` 且提示信息可读。
- **触及文件**：`test/units.test.ts`（新建）
- **验证方式**：`npx vitest run test/units.test.ts` 全部通过；全程无网络请求、无 mock。

### T7 真实集成测试

- **要做什么**：新建 `test/integration.test.ts`，全部走真实 API（禁 mock，需有效的 `OPENCODE_API_KEY`）：
  - 真实 LLM 最小推理冒烟（经 OpenCode Go 调用，确认 key 与模型 `muse-spark-1.3-contributor` 可用）；
  - `fetchStatic` 抓取真实靶场页面，验证内容与链接提取；
  - `renderDynamic` 对 JS 渲染靶场（https://quotes.toscrape.com/js）走真实浏览器渲染路径，验证能取到渲染后内容（或驱动 agent 以 render=true 路径抽取记录）；
  - 端到端：`createCrawlerAgent` 驱动真实 agent 对带分页的靶场（quotes.toscrape.com）连续抓取 ≥2 页，验证各页记录均结构化落盘 JSONL、每行为可直接解析的 JSON 对象（无双重编码）。
- **触及文件**：`test/integration.test.ts`（新建）
- **验证方式**：设置有效 key 后 `npx vitest run test/integration.test.ts` 全部通过；检查落盘 JSONL 每行 `JSON.parse` 成功且字段值为原始类型/对象。

### T8 README.md 完善

- **要做什么**：完善 `README.md`：安装步骤（Node >= 22.19、npm install）、配置说明（逐项列出全部三个环境变量：`OPENCODE_API_KEY`（必填）、`CRAWLER_MODEL`（默认 `muse-spark-1.3-contributor`）、`OPENCODE_SESSION_ID`（可选，固定会话路由），与 DESIGN Configuration 表对齐）、使用方式（`npm run crawl` 及 CLI 参数）、架构说明（config / errors / page / tools / agent / cli 各模块职责）、常见问题故障排查（key 失效、网络失败、渲染兜底、Ctrl+C 清理）、测试说明（`npm test` 及真实 API 前置条件）。
- **触及文件**：`README.md`
- **验证方式**：按 README 从零走一遍安装-配置-运行-测试流程可成功；文档覆盖 AC9 要求的全部主题。

### T9 最终验证

- **要做什么**：全量回归——`npm run typecheck` 零错误；`npm test`（即 `vitest run`）全部通过；真实跑一次爬取（对指定入口 URL 执行 `npm run crawl`），确认 agent 自主抓取、分页跟随、JSONL 落盘全链路正常。
- **触及文件**：无新增改动（只做验证；如发现问题回修对应任务）
- **验证方式**：三条命令的输出均可证明通过（typecheck 无输出、vitest 全绿、爬取产生含记录的 JSONL 文件）。

## Test Strategy

- **禁 mock**：所有测试必须走真实 LLM API 与真实网络，不使用任何 mock/fixture 替身（REQ 硬约束）。
- **运行方式**：`npm test` 即 `vitest run`（package.json scripts 已配置），一条命令跑全部测试。
- **分层**：
  - 纯函数层（`test/units.test.ts`）：无网络依赖，覆盖 pageToLLMView / extractLinks / truncate / save_record 双重编码还原 / config 缺 key 报错，可随时快速回归；
  - 真实集成层（`test/integration.test.ts`）：需有效的 `OPENCODE_API_KEY`，覆盖 LLM 最小推理（OpenCode Go）、fetchStatic 真实靶场抓取、端到端 agent 抓取落盘。
- **回归门槛**：T9 以 `npm run typecheck` 零错误 + `npm test` 全绿 + 一次真实爬取成功作为最终验收。

## Risks

- **真实 API 测试依赖网络与 key 有效性**：集成测试在无网络、key 过期或配额耗尽时会失败；这是 REQ 明确接受的约束，需在 README 的测试说明与故障排查中写清前置条件，失败时区分"环境问题"与"代码缺陷"。
- **Playwright 在 CI 的稳定性**：`renderDynamic` 依赖 Playwright 浏览器，在 CI 环境可能因浏览器二进制缺失、版本不匹配或沙箱限制而不稳定；需保证本地 `npx playwright install` 指引清晰，CI 上必要时单独安装浏览器依赖。
