## Goal

把现有 4 个工具重构为取（fetch）/懂（extract）/存（save）3 个本质工具，让 save 内建数据契约，修复量子位暴露的 schema 漂移 / 重复 / 空值三缺陷。

## Tasks

### T1 重构 fetch

- **要做什么**：在 `src/tools.ts` 把 `fetch_page` 改名为 `fetch`，参数保持不变（`{ url, render? }`），返回值保持不变（`{ url, status, markdown, links }`）；同步更新工具 label 与 description，强调"静态取失败或内容不足时改用 `render=true` 重取、返回的 `links` 可用于识别分页/详情链接"。
- **触及文件**：`src/tools.ts`
- **验证方式**：`npm run typecheck` 通过；`fetch` 工具以新名字注册且 description 覆盖渲染策略与分页提示。

### T2 新增 extract 工具

- **要做什么**：在 `src/tools.ts` 新增 `extract({ content, instruction, selector? })`。
  - 给了 `selector`：走确定性路径，用 cheerio 对 `content`（HTML）按 `selector` 提取文本/属性，返回 `{ text: string[] }`。
  - 没给 `selector`：走 LLM 路径，新建 `src/extract-llm.ts`，用 pi-ai 的 `createModels` + `opencodeGoProvider` + `streamSimple` 做**独立一次**调用（content 截断后拼接 instruction → JSON），返回 `{ records: unknown[] }`。关键约束：不经 agent loop，避免嵌套 agent 递归。
- **触及文件**：`src/tools.ts`、`src/extract-llm.ts`（新建）
- **验证方式**：`npm run typecheck` 通过；`extract` 两条路径返回结构与设计契约一致（selector → `{ text }`，LLM → `{ records }`）。

### T3 save 契约

- **要做什么**：在 `src/tools.ts` 把 `save_record` 改名为 `save({ data, schema?, dedup_key? })`，加入三条契约规则：
  1. `schema` 存在性校验——`data` 缺任一 schema 字段 → 拒绝（`saved: false`，`reason` 指明缺失字段）。
  2. `dedup_key` 查重——在 `records.jsonl` 中查同 key 记录，重复 → 跳过（`saved: false`，`reason: duplicate`）。
  3. 全空过滤——内容字段（`schema` 中除 `dedup_key` 外）全空 → 过滤拒绝。
  - 保留现有双重编码还原逻辑。
  - 返回 `{ saved: boolean, reason?: string, count: number }`。
- **触及文件**：`src/tools.ts`
- **验证方式**：`npm run typecheck` 通过；三条规则各自可触发；`count` 为写入后记录总数。

### T4 更新 systemPrompt

- **要做什么**：在 `src/agent.ts` 更新 systemPrompt，引导 agent：
  - 使用取/懂/存三工具完成任务；
  - 渲染策略——静态取失败或内容不足时改用 `render=true`；
  - 分页识别——从 `fetch` 返回的 `links` 中识别"下一页"并再次调用 `fetch`；
  - 统一用 `save` 的 `schema` + `dedup_key` 落盘以保证契约。
- **触及文件**：`src/agent.ts`
- **验证方式**：`npm run typecheck` 通过；prompt 覆盖三工具用法、渲染策略、分页识别与契约落盘要点。

### T5 units 测试

- **要做什么**：在 `test/units.test.ts` 增加/保留用例：
  - `save` 契约三规则各一个用例：缺字段拒绝 / 重复跳过 / 全空过滤；
  - `extract` 的 selector 路径（用 cheerio 合成 HTML 做确定性抽取）；
  - 保留现有 `pageToLLMView` / `extractLinks` 用例。
- **触及文件**：`test/units.test.ts`
- **验证方式**：`npx vitest run test/units.test.ts` 全部通过；全程无网络、无 mock。

### T6 integration 测试

- **要做什么**：在 `test/integration.test.ts` 增加用例（真实 API / 真实文件，禁 mock）：
  - `extract` 的 LLM 路径用真实模型抽取结构化记录；
  - `save` 契约走真实文件系统读写；
  - 端到端——agent 用三工具抓 `quotes.toscrape.com` 多页，验证分页内化于 `fetch`；
  - 重跑同一站点，验证 `dedup` 不产生重复记录（对应 REQ AC6 量子位缺陷修复）。
- **触及文件**：`test/integration.test.ts`
- **验证方式**：设有效 key 后 `npx vitest run test/integration.test.ts` 通过；重跑后 `records.jsonl` 无重复、字段结构一致。

### T7 适配输出与文档

- **要做什么**：
  - 更新 `src/cli.ts` 中工具事件的打印，适配新工具名（若有对 `fetch_page` / `save_record` 的硬编码）；
  - 更新 `README.md`，说明取/懂/存三工具的用途与参数。
- **触及文件**：`src/cli.ts`、`README.md`
- **验证方式**：`npm run typecheck` 通过；运行 CLI 时工具事件以新工具名正确打印；README 三工具说明与设计契约一致。

### T8 最终验证

- **要做什么**：全量回归——`npm run typecheck` 零错误；`npm test`（`vitest run`）全绿；真实端到端跑一次（含重跑验证去重）。
- **触及文件**：无新增改动（仅验证；发现问题回修对应任务）
- **验证方式**：三条命令输出均可证明通过（typecheck 无输出、vitest 全绿、端到端 + 重跑后记录无重复）。

## Test Strategy

- **禁 mock**：所有测试走真实 LLM API 与真实网络，不使用 mock/fixture 替身（REQ 硬约束）。
- **运行方式**：`npm test` 即 `vitest run`（package.json scripts 已配置），一条命令跑全部测试。
- **分层**：
  - units（`test/units.test.ts`）：无网络依赖，覆盖 `pageToLLMView` / `extractLinks` / `save` 契约三规则 / `extract` selector 路径；
  - integration（`test/integration.test.ts`）：需有效 key，覆盖 `extract` LLM 路径真实模型抽取、`save` 契约真实文件、端到端 agent 三工具抓多页、重跑去重验证。
- **契约验证**：`save` 契约基于真实文件系统读写验证，非内存替身。

## Risks

- **extract LLM 路径独立调用增加 token**：`extract` 的 LLM 路径用独立一次 `streamSimple` 调用，会给整条链路增加额外 token 消耗；需与主 agent loop 的预算共同观测（见 DESIGN Open Question 1）。
- **契约过严影响灵活性**：`save` 的强制契约在开放式探索场景可能阻碍写入；缓解方式为契约字段均为可选启用（不传 `schema` / `dedup_key` 即不校验，见 DESIGN Open Question 2）。
- **dedup 依赖 dedup_key 稳定**：去重正确性依赖 `dedup_key` 取值稳定，实践中使用 `url` 作为去重键。
