## Goal

为每次 crawl 记录全量 trace（LLM prompt/response + 工具调用）到 node:sqlite，旁路异步落盘，可查行为模式，让 agent 行为完全可观测。

## Tasks

### T1 新建 src/trace.ts：TraceStore + TraceCollector

- **做什么**：
  - `TraceStore` 类封装 `node:sqlite` 的 `DatabaseSync`，db 文件默认 `output/trace.db`。
  - 建三表 + 索引，开启 WAL 模式：
    - `runs`：`id`（PK，run_id）、`url`、`task`、`started_at`、`ended_at`、`status`、`records_saved`、`duration_ms`。
    - `llm_events`：`id`、`run_id`、`turn`、`direction`（`prompt` / `response`，一行一方向）、`payload_json`、`model`、`usage_json`、`created_at`。
    - `tool_events`：`id`、`run_id`、`turn`、`tool_call_id`、`tool_name`、`args_json`、`result_json`、`is_error`、`duration_ms`、`saved`（INTEGER：`save` 工具调用导致落盘时记 1，否则记 0；非 save 工具记 NULL）、`created_at`。
    - 索引：`llm_events(run_id)`、`tool_events(run_id)`、`tool_events(tool_name)`、`tool_events(tool_call_id)`、`tool_events(run_id, tool_name)`。
  - `TraceCollector` 类：
    - `start(runMeta)`：生成/登记 `run_id`，运行开始时 INSERT `runs` 起始行（含 `url`、`task`、`started_at`、`status='running'`），返回 `runId`。
    - `attach(agent)`：调用 `agent.subscribe`，收集：
      - `message_end`（assistant response）
      - `tool_execution_*`（args、result、isError、durationMs、saved）
      - turn 归属计数（每次 LLM 往返递增 turn，工具调用归属当前 turn）
    - 深拷贝（`structuredClone`）进内存缓冲，避免后续被引用变更污染。
    - 提供 `onPayload` 回调，用于收集完整 prompt。
    - `flush()`：批量写库，整段 `try/catch` 旁路，失败仅 `console.warn`，绝不抛出；缓冲达到事件阈值时自动触发一次 flush。
    - `close(runId, status, recordsSaved)`：结束时 UPDATE `runs` 行（写 ended_at / status / records_saved / duration_ms）。
    - db 初始化失败降级为"仅内存日志"（旁路），运行继续。
- **文件**：`src/trace.ts`（新建）
- **验证**：`npm run typecheck` 通过；可手动构造 collector 并 flush 后查表存在数据。

### T2 agent.ts：注入 trace 挂点

- **做什么**：`createCrawlerAgent` 增加可选参数 `trace?: TraceCollector`；将其包成 `onPayload` 传入 `new Agent`，实现完整 prompt 埋点；onPayload 返回 `undefined`（旁路，不改变 agent 行为）。
- **文件**：`src/agent.ts`
- **验证**：`npm run typecheck` 通过；不传 trace 时行为与现状一致（无参兼容）。

### T3 cli.ts：生命周期接线

- **做什么**：
  - 创建 `TraceCollector` + 生成 `runId`，`attach(agent)`。
  - run 结束后 `flush()` + `close(runId, status, recordsSaved)`。
  - 打印 trace 路径、`run_id` 以及查询提示（如 `npm run trace -- <run_id>`）。
  - `SIGINT` 时同样 `flush()` + `close(status='aborted')`。
- **文件**：`src/cli.ts`
- **验证**：手动 `npm run crawl` 后 `output/trace.db` 有对应 run 数据；Ctrl+C 中断时 runs 状态为 `aborted`。

### T4 新建 src/trace-query.ts + package.json script

- **做什么**：
  - 列出 runs（按 `started_at` 排序，支持时间过滤），覆盖"按运行/工具/时间查询"的运行与时间维度。
  - 回放某 run 的完整事件流（按 turn 顺序输出 llm_events + tool_events）。
  - 查 **extract-no-save** 模式：某 run 存在 `tool_events` 中 `tool_name='extract'` 且 `result_json` 记录数 > 0，但同 run 无 `save` 工具调用、且无 `saved=1` 记录。
  - `package.json` scripts 加 `"trace": "tsx src/trace-query.ts"`。
- **文件**：`src/trace-query.ts`（新建）、`package.json`
- **验证**：`npm run trace -- <run_id>` 能打印事件流；extract-no-save 查询返回预期结果。

### T5 units 测试

- **做什么**：真实 agent 跑最小真实 LLM 抓取产生 trace，断言：
  - `output/trace.db` 中存在 `runs` 行；
  - `llm_events` 含 prompt + response；
  - `tool_events` 有工具调用且字段完整（含 `saved`：save 调用为 1，其余为 0/NULL）；
  - turn 归属正确；
  - 按 `tool_call_id` 关联正确。
- **文件**：`test/` 下 unit 用例（新增）
- **验证**：`npm test` 该用例通过。

### T6 integration 测试

- **做什么**：端到端 crawl 一个真实站后查 `trace.db`：
  - (a) 能回放完整事件流；
  - (b) `tool_events.saved` 字段断言正确（save 调用 = 1，其余 0/NULL），且 extract-no-save 查询能正确返回（构造一次已知无 save 的运行验证查询准确）；
  - (c) trace 记录失败不影响抓取（旁路）。
- **文件**：`test/` 下 integration 用例（新增）
- **验证**：`npm test` 该用例通过。

### T7 用 trace 回答 AC8 两个悬案

- **做什么**：跑一次 GitHub Trending 抓取，查 `trace.db` 确认：
  - (a) extract 后 agent 是否真没调 save（看 `tool_events` 序列）；
  - (b) `records.jsonl` 清空是否 crawl 流程所为（看有无 save 写库 / 工具调用记录）。
  - 把结论写进证据。
- **文件**：证据文档（如 `docs/superpowers/` 下证据记录）
- **验证**：结论有 trace.db 数据支撑，可复现。

## Test Strategy

- 禁 mock，真实运行：unit/integration 均调用真实 agent / 真实 LLM / 真实站点。
- node:sqlite 零依赖：使用 Node 22 内置 `DatabaseSync`，不新增依赖。
- `npm test` = `vitest run`。
- trace 断言读 `output/trace.db` 实际落库数据。

## Risks

- **node:sqlite 实验性 API 变动**：Node 内置模块标记 experimental，将来 API 可能调整；实现隔离在 `TraceStore` 单点，便于替换。
- **全量 payload 体积大**：prompt/response 全量存储会使 db 迅速膨胀；加体积告警。
- **旁路写库仍可能微拖慢**：即使旁路，写库仍有开销；用批量 flush 缓解。
