## Summary

按第一性原理提供取（Fetch）/ 懂（Extract）/ 存（Save）三个本质工具，策略差异内化为参数，并内建数据契约。

## Requirement Reference

本特性对应需求 [REQ-e1f94248](../requirements/REQ-e1f94248.md)（P1 本质内核：取/懂/存 三工具），其 8 条验收标准的精简版如下：

1. 通过"取"取得静态页面内容与链接；内容不足或失败时改用渲染取得渲染后内容
2. 通过"取"识别返回链接中的分页并连续抓取多页（分页内化于取，非独立工具）
3. 通过"懂"用确定性选择器从页面提取目标数据
4. 通过"懂"用 LLM 按字段说明从页面语义化抽取结构化记录
5. 通过"存"落盘时可声明字段集合与去重键：缺字段被拒、同去重键重复被跳过、全空内容被过滤
6. 重跑同一站点，数据契约保证不产生重复记录、字段结构一致（修复量子位暴露的 schema 漂移 / 重复 / 空值三缺陷）
7. 全部测试真实 API / 网络、禁 mock，`npm test` 一键通过
8. 给真实站点 URL + 自然语言任务，agent 能组合取 / 懂 / 存完成并产出结构化结果

## Key Decisions

本次需求澄清确定的关键决策：

- **(a) 第一性原理**：只切分为取 / 懂 / 存三个本质工具，拒绝按技术实现冗余拆分。
- **(b) 渲染内化**：渲染是"取"的参数，而非独立工具。
- **(c) 分页内化**：分页内化于"取"，由 agent 从返回链接中识别"下一页"再次调用"取"，非独立工具。
- **(d) 抽取双路径**：确定性选择器与 LLM 语义抽取是"懂"的两条路径，按结构明确程度选择。
- **(e) 存带契约**：数据契约（schema / dedup_key / 空值过滤）内建于"存"。
- **(f) 演进策略**：在现有项目上演进，复用 config / errors / page 基础。
- **(g) 测试策略**：禁 mock，走真实 API / 网络。
