## Summary

为每次 crawl 记录全量 trace（LLM 完整 prompt/response + 每次工具调用）到 SQLite，支持回放与查询，让 agent 行为完全可观测。

## Requirement Reference

引用 REQ-d53c7143（P2 可观测性：crawl 行为全量 trace 与查询），其验收标准如下：

- 每次 crawl 产生一条独立运行记录（入口 URL、任务描述、起止时间、最终状态）
- 记录每次 LLM 交互，含完整 prompt 与完整 response（全量不截断）
- 记录每次工具调用，含工具名、入参、输出/错误、耗时、是否落盘
- trace 持久化到 SQLite，跨运行保留、可按运行/工具/时间查询
- 提供查询能力，能查出"extract 有产出但无后续 save"这类行为模式
- trace 旁路：记录失败不影响 crawl 主流程
- CLI 结束时打印本次 trace 标识与查询入口
- 能直接回答两个悬案：(a) GitHub Trending 为何 extract 后无 save；(b) records.jsonl 是否被 crawl 流程清空
- 全部测试真实运行、禁 mock，npm test 一键通过

## Key Decisions

- (a) 可观测性是调试前提，优先于修具体 bug：先让行为可见，再谈定位根因。
- (b) 全量 trace 含完整 prompt/response：用户明确要求，接受由此带来的大存储开销。
- (c) SQLite 嵌入式存储：支持查询"extract 后无 save"等行为模式，跨运行保留。
- (d) trace 走旁路：记录失败不影响抓取，可观测性不得成为主流程的故障源。
- (e) 不破坏现有"取 / 懂 / 存"内核。
- (f) 禁 mock，全部测试真实运行。
