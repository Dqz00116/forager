## Summary

给 agent 增加"求助"这一本质工具：遇到登录/验证码/拖拽等需要人操作的场景时弹出有头浏览器让人操作，完成后同一会话接管继续（登录态保留）。

## Requirement Reference

本特性对应需求 [REQ-d5bb0185](../requirements/REQ-d5bb0185.md)（P3 人机协作：agent 求助与人交互接管），其 10 条验收标准的精简版如下：

1. agent 拥有"求助"能力：遇到需人操作的场景（登录/验证码/拖拽/权限墙）时能主动发起求助并说明需要人做什么
2. 求助时弹出人可操作的真实浏览器窗口（有头模式），显示目标页面
3. 人在该窗口完成交互后，能通过简单方式（如回车）告知 agent 继续
4. 人完成交互后，agent 在同一会话中继续抓取，登录态/Cookie 自然保留（同一浏览器上下文延续）
5. 求助期间 agent 暂停等待，不会并发执行其他动作导致状态混乱
6. 人取消或中断（如 Ctrl+C）时，agent 能正确清理浏览器资源并退出
7. 不需要人介入的任务，agent 仍以无头模式高效运行（有头窗口仅在需要时出现）
8. 求助与接管过程被记录进 trace（何时求助、人操作耗时、何时接管）
9. 提供一个需要登录的真实场景验证：agent 求助 → 人登录 → agent 继续抓到登录后内容
10. 全部测试真实运行、禁 mock（人机交互环节可用受控方式模拟人的回车动作），`npm test` 一键通过

## Key Decisions

本次需求澄清确定的关键决策：

- **(a) 能力边界**：承认 agent 的能力边界，人是系统的一个组件，不追求虚假的全自动。
- **(b) 本质动作**：求助是第 4 个本质动作，与取、懂、存并列。
- **(c) 触发方式**：由 agent 主动调用求助工具触发。
- **(d) 有头策略**：有头窗口仅在需要时出现，默认无头。
- **(e) 登录态延续**：同一浏览器上下文延续，登录态/Cookie 自然保留。
- **(f) 并发控制**：求助工具 `executionMode=sequential`，防止并发。
- **(g) 可观测**：求助/接管记入 trace。
- **(h) 测试策略**：禁 mock，真实测试（人的回车用受控模拟）。
